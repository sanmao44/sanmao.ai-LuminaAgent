# SANMAO.AI 增量产品升级路线

## 最终目标

在保留现有业务能力和封板架构的基础上，持续提升创作效率、自动化可靠性和界面品质。用户用更少操作完成创作、编辑、生成和管理；界面层级清晰、视觉统一、排版舒适，长任务有明确反馈，失败后能恢复。

完成一个可验证的产品切片，再扩大能力范围。优先减少重复输入、重复请求和失败后的返工。

## 当前基础与本轮落点

- 部署形态为 Modular Next Monolith，架构已封板。Agent Application、Provider Coordinator、Worker、Task Runtime、CanvasCore 和 Repository 继续作为各自领域的唯一 owner。
- 已有 Agent 快捷创作路线、继续最近创作、提示词优化、任务日志、图片参数恢复、视频任务恢复和 Provider 容错链路。优先把这些能力串顺，避免再建立一套编排或存储系统。
- `app/page.tsx` 仍是 Legacy Integration Surface；视频任务类型和存储适配仍位于 `lib/video-task-store.ts`。历史视频恢复只增加 UI composition 和现有 Worker 的纯读接口。
- 已完成切片：历史视频日志跨分页恢复。详情按需读取原任务快照，保留完整输入；重复点击去重，关闭或切换详情后取消旧请求，失败时保留详情并提示原因。
- 快照 GET 使用 `refresh=false`，保持鉴权且禁止缓存；恢复参数不刷新 Provider、不推进任务状态、不重新提交生成。默认 GET 仍保留既有任务刷新行为。
- 读到的任务仅作为恢复输入，不写入当前分页列表，也不建立新的任务 authority。最终恢复仍交给 VideoStudio 及其现有确认交互。
- 进入 VideoStudio 后，其既有后台任务刷新仍会运行；纯读保证只覆盖恢复所用的快照查询，不改变正在运行的任务的追踪机制。
- 本轮执行优化：图片工作台同会话草稿自动保存与恢复；超分 Provider 瞬时轮询失败后沿用原任务退避续查。两者分别复用现有存储会话和 Task Runtime / Worker 追踪能力，没有新增队列或任务 authority。
- 图片生成日志超过两小时仍未收到回执时，保留 `provider_result_unconfirmed` 语义；恢复流程继续显示待核对并阻止自动重提，只有明确终态失败才开放重试，避免超时被误当作服务商已失败。
- 普通图片生成任务在刷新恢复或收到“服务商已接收”结果后，会自动进行一次只读日志核对；核对仍未完成时保留任务卡和手动入口，不自动重提或新增 Provider 调用。

## 优先级与验收

| 阶段 | 交付重点 | 接入边界 | 验收标准 |
| --- | --- | --- | --- |
| P0：可靠恢复 | 跨分页恢复、请求去重、错误与等待反馈、失败后保留输入 | 现有 client adapter、Worker query、UI interaction | 任意现存视频任务可从日志恢复；关闭详情无延迟跳转；快照读取无生成请求 |
| P1：减少操作 | 图片/视频/Agent 的恢复、复用、继续编辑入口统一；推荐下一步操作 | 现有 presentation projection、Canvas Command、Agent Application | 常用路径动作数下降；推荐有依据、可编辑，由用户确认收费操作 |
| P1：视觉与信息架构 | 明确“创作入口—工作台—结果管理—设置”的层级；统一标题、间距、空态、状态与错误操作 | 现有组件、CSS token、主题与响应式规则 | 桌面/移动端、明暗主题无内容溢出；主要操作和当前状态可快速辨认 |
| P2：小型自动化链路 | 有限并发批量任务、可选后处理、保存版本、明确的重试策略 | Worker / Task Runtime、现有 Repository、Provider Coordinator | 任务可取消、可追踪；重启与重试不重复扣费；成功结果不因局部失败丢失 |
| P3：高级编排 | 定时生成、多模型串联、人工暂停与恢复、可视化步骤 | AgentRun / Task Contract、Application、CanvasCore projection | 先交付一条真实工作流，再考虑通用画布；执行状态和编辑状态各有明确 owner |

视频与图片工作台草稿均已接入同会话保存，刷新后恢复提示词及可恢复设置；参考素材本体不写入草稿，恢复后提示重新添加。恢复不会自动提交任务。显式任务参数和用户新输入优先；Agent 编辑草稿体验仍待评估。草稿仅限同一浏览器会话，不是跨设备或永久保存。

## 集成时必须处理的实际问题

- **限流和重试**：在既有 Provider / Worker owner 内实现有限并发、退避和 Retry-After；参数错误与权限错误直接反馈，提交结果未知时先查询，避免盲目重放收费调用。
- **状态同步**：UI 列表是投影，按任务 ID 关联结果。过期请求不得覆盖新筛选或新详情，读取失败不得被解释成任务已删除。
- **超时与取消**：区分 UI 取消读取、停止本地追踪、取消上游任务三种语义；长任务使用已存在的任务查询链路，脱离单次 HTTP 请求存活。
- **资源开销**：日志详情按需加载；批量生成和后处理设置并发、数量、体积与保留期上限，版本优先复用现有存储和快照机制。
- **权限与成本**：所有查询继续走现有鉴权边界；日志和遥测不暴露密钥；新增自动执行遵循现有确认与授权策略。

## 验证方式

每个切片先跑相关行为测试，再运行 `npm run check`（已包含 typecheck、更新清单、全量测试和生产构建），最后检查 `git diff --check`。UI 以隔离的合成数据验证加载、错误、取消、响应式和主题，避免产生真实模型费用。

后续记录真实用户路径的操作数、任务成功率、重复提交率、失败恢复率和等待期间退出率。先建立基线，再按切片比较收益，不以引入库的数量衡量现代化。

### 本轮执行自动化切片：视频结果自动归档重试

- `lib/video-storage.ts` 对远程视频下载增加有限重试：最多 3 次、总时限 3 分钟；网络异常、超时、408/425/429/5xx 进入退避，`Retry-After` 等待有上限。
- 401/403/404/410、体积超限、格式处理和本地写盘错误保持立即失败；多视频任务仍按现有策略清理部分归档，并保留服务商远程地址作为可用结果。
- 重试只发生在 Storage Adapter 内，不重新提交服务商任务、不改变 Task Runtime owner，减少网络瞬断后的手动“再次保存”。
- 定向视频存储与任务输出测试 10 项通过；`npm run typecheck` 与 `git diff --check` 通过。

### 本轮执行自动化切片：视频工作台草稿自动保存

- 视频工作台自动保存提示词、模型、操作类型、时长、比例、分辨率及 Agnes 参数到版本化 `sessionStorage`；刷新或离开后重返同一浏览器会话时恢复，不触发生成或扣费。
- 图片、视频和音频素材本体不写入草稿；恢复后切回纯文本模式并提示重新添加素材，避免大型 Data URL 挤占浏览器存储。
- 存储读取、配额或写入失败均有显式状态；显式任务/提示词预填优先呈现，跳过本次自动恢复并保留原草稿，待用户开始操作后才写入新状态。
- 历史参数恢复的覆盖确认同时检查提示词、媒体和全部生成参数，包括 Agnes 尺寸、帧数与帧率；只调整这些高级参数也会先确认。
- 图片工作台及 Agent 草稿恢复一致性仍待评估；会话草稿不是跨设备或永久保存。
- 定向草稿存储行为测试 4 项通过；刷新恢复逻辑及显式预填保护已代码检查。完整 `npm run check` 结果见本轮验证，跨工作台切换的浏览器实测仍待完成。

### 本轮执行自动化切片：后台推进视频与超分任务

- 根目录 `instrumentation.ts` 仅在生产 Node.js 服务启动 Worker-owned reconciler；本地开发默认不推进持久化任务。调度器按到期时间读取活动任务，最多同时推进 2 项、每轮最多 12 项，并复用已有刷新、退避、幂等和超时逻辑。
- 视频历史列表不再对每条记录触发 Provider 刷新；单任务路由保留旧的默认刷新行为，同时支持 `?refresh=false` 纯读。工作台轮询只读取状态，任务推进由后台 Worker 持续承担。
- 超分任务在 Provider 回执落库前中断时，不会被重新提交；超过现有 20 分钟任务时限后会收敛为可见超时失败。缺少 Provider 轮询能力的异步任务会结束为明确失败，避免一直占据活动状态。
- 到期任务按 `nextPollAt`、创建时间排序后再分页，避免新任务挤占旧任务；定向行为测试覆盖多类任务连续三轮推进。存储查询扫描完整任务仓储而不是仅读最近 500 条，因此早期未完成任务仍能恢复推进。
- 当前部署按单体服务进程运行；关闭浏览器不影响任务，退出服务进程时推进暂停并会在下次服务启动后恢复。多服务实例仍需持久 claim/lease 协调，本轮未引入该复杂度。
- 定向验证覆盖并发上限、失败隔离、旧活动任务扫描和纯读查询；全量验证结果记录在本轮交付报告中。

### 本轮执行智能化切片：项目视觉参考自动复用

- Canvas 项目的默认视觉参考会附加到符合条件的图片生成和 reference 模式视频生成请求，减少重复挑选素材；显式节点参考优先，预览显示模型上限下实际会提交的项目图，并标明排除、去重和截断状态。
- `@` 明确引用或改图操作不会附加项目默认图；图片自动识别为改图时也会跳过默认图。项目与版本快照保存稳定素材 ID，项目包仅携带这些关联 ID，不包含只存在于全局素材库中的图片本体；跨安装迁移需重新关联缺失素材。
- 初版定向测试 78 项通过；初版 `npm run check` 完整通过，含 typecheck、更新清单、全量测试（2,457 通过、1 跳过）和生产构建，静态页面 58 个。
- 本轮在既有桌面 Canvas 上检查了 1904×915 视口，无页面横向溢出或可见 alert；当前项目未配置默认参考，因此没有在浏览器中触发展示该预览的交互验证。未触发真实收费生成，Provider 输出质量仍未验证。
- 复核后补充有效请求投影：显式图优先，按图片/视频上限标注本次发送、排除、去重或截断；`@` 引用和改图会说明默认图不参与，图片自动模式保留编辑分支提示。更新后定向测试 22 项、全量测试 2,460 项通过且 1 项跳过，typecheck 与更新清单校验通过。更新后的生产构建未运行，因为当前 3210 服务仍承载用户画布和运行任务；初版构建结果不覆盖本次 UI 修正。

### 本轮执行自动化切片：图片草稿恢复与超分轮询退避

- 图片工作台在设置恢复完成后自动保存提示词、生成/超分模式和“参考素材未持久化”标记到有版本号与长度限制的 `sessionStorage`。不保存参考图、蒙版或 Data URL；刷新后恢复不会自动生成或产生收费调用。
- 用户开始输入、切换工作流或显式恢复历史任务时，优先保留当前操作；提示词旁展示恢复、保存或存储失败状态。若草稿曾有参考素材，恢复后提示重新添加。
- 超分 Provider 轮询遇到网络瞬断或 408/425/429/5xx 时保留原任务和上游任务 ID，按 `Retry-After` 或指数退避安排后续查询；原任务仍受既有任务超时约束。权限、参数及结果落盘错误不走轮询重试，也不会因查询失败重新提交上游任务。

### 本轮执行自动化切片：图片生成结果待确认与恢复

- 图片生成遇到服务商表示已接收但结果未确认、响应中断、空结果或本机归档失败时，任务保留为“待核对”，记录原任务 ID；核对前不开放重新提交，避免结果未知时重复调用或重复扣费。
